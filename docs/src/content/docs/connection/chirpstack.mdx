The ChirpStack backend supplies device inventory, live events, and downlinks over
gRPC. Provision devices and gateways in ChirpStack, then connect with an API key.

## Connect your collection

Install the backend with `pip install "lorawan-connection[chirpstack]"`.

Save the [SenseCAP example library](/lorawan-connection/getting-started/quickstart/#example-library)
as `sensecap_lorawan.py`. Save the script below as `connect_sensors.py` in the same
directory. Set `CHIRPSTACK_SERVER` to your server URL and `CHIRPSTACK_API_KEY` to
your API key. Set `CHIRPSTACK_TENANT_ID` if your key cannot list tenants.

```sh
python connect_sensors.py
```

The script prints supported devices and readings from all applications accessible
to the key. A disconnect or Ctrl+C closes the collection and connection.

## Existing devices and events

The backend polls the device list every 30 seconds and opens an internal ChirpStack
event stream for each device. Catalog profiles supply model and vendor identities.
An incomplete read preserves the previous device list. Custom profiles without
catalog identity remain visible but do not select a device model.

Generated protobuf payloads pass through the event envelope by reference. The internal
stream returns JSON, so each payload must first be parsed into a generated message.
Newly observed devices receive an `ADDED` event before their activity is delivered.

The internal API is a compatibility dependency, tested against ChirpStack 4.19.2 and
Python bindings 4.19.0. It requires device event retention to be enabled. ChirpStack can
send retained events when a stream opens, followed by live events. The backend
records the local time before opening each device stream, with five seconds of leeway.
It accepts server receipt timestamps at or after that time minus five seconds and
drops older events. This also applies to devices discovered later.

Keep the client and ChirpStack clocks synchronized. The filter uses the Redis event
ID's timestamp, not the sensor's clock. Clock differences can drop new events or
admit retained ones. Missed telemetry is not recovered.

## API reference

`ChirpStackConnection(endpoint, api_key, *, tenant_id=None, application_ids, network_id,
poll_interval=30, channel=None)` owns its channel, including an injected test channel.

| Method or attribute | Behavior |
| --- | --- |
| `await tenants()` | Return `{tenant_uuid: name}`. A scoped key may be denied. |
| `await applications()` | Return `{application_uuid: name}` for the selected tenant, or all accessible tenants when `tenant_id` is `None` (the default). |
| `await inventory()` | Read descriptors without starting streams or updating the current device list. |
| `await async_connect()` | Read existing devices and start polling and live events. |
| `await async_subscribe(*, brands, callback)` | Report matching existing devices, then live events. Return an unsubscribe function. `brands=None` includes all vendors. |
| `on_disconnect(callback)` | Register a callback with no arguments; return an unsubscribe function. |
| `await async_send_downlink(downlink)` | Validate device scope and enqueue application bytes; return the queue-item UUID. |
| `await refresh()` | Refresh the connected device list. |
| `await close()` | Stop tasks, await cleanup, and close the channel. |
| `devices` | Current devices, keyed by DevEUI. |
| `available` | Whether the connection can deliver events. |
| `error` | The last connection failure, or `None`. |

The backend retries a failed device stream independently. Three consecutive stream
failures or device-list polling failures mark the connection unavailable. A rejected
key or access scope fails immediately. Live events continue while a device-list
refresh is in progress.

Events delivered before a collection subscribes are not buffered. The five-second
leeway does not guarantee initial readings.

`brands=None` is a backend extension for discovery tools. Device libraries and
`MockConnection` use the `Connection` protocol with an explicit set of stack and brand pairs.

Callbacks run synchronously. Callbacks registered with `on_disconnect()` run after `available` becomes
false. Create a new connection to recover. `AuthenticationError` reports rejected
credentials or access scope; `ConnectionUnavailable` reports other subscription failures.
ChirpStack can return the same authentication error for an invalid key and missing
permission. Discovery methods retain gRPC errors so callers can offer a tenant-ID fallback.

## Write access

Downlinks use the public `DeviceService.Enqueue` gRPC method. The connection must
be connected, and the device must belong to its selected applications.
Before enqueueing, the backend reads the device to check its current application.
Use a tenant API key with write access for commands. A read-only key still supports
device discovery and live events; attempted writes raise `DownlinkError`.

`Downlink(dev_eui, f_port, data, confirmed=False, expires_at=None)` contains plaintext
application bytes. FPort must be 1–223. An optional expiry is a timezone-aware datetime.
ChirpStack owns encryption, frame counters, scheduling, and expiry. The helper never
flushes existing commands or retries an ambiguous RPC result.

The backend's returned queue ID means accepted, a `TX_ACK` means transmitted, and a positive
`ACK` means the device acknowledged a confirmed downlink. Models interpret device
reports to determine whether the requested action took effect.

`Device.async_send_downlink()` uses this sender and waits for the corresponding
ACK by default. The backend method itself returns after enqueueing. See
[sending commands](/lorawan-connection/modelling/overview/#send-commands) for caller timeouts.
