Build the collection, decoder, and device models in a Python library. Keep server
credentials and application-specific code in the consuming application.

Start with this structure as the library grows:

```text
sensecap_lorawan/
  collection.py     # supported catalog identities and model factory
  device.py         # shared state subscriptions and lifecycle
  models/           # typed models and state
  decoders/         # byte-level vendor formats
examples/           # standalone capture replay
tests/              # decoder and event-sequence tests
```

The S2101 example below fits in one file. It lives under `examples/` and is excluded
from the `lorawan_connection` wheel.

## Select models by catalog identity

The collection recognizes vendor `744` (`0x02E8`) and S2101 model
`fc455aa2-01cf-492b-9359-a5d8c9a0e1b3`. These are the identities tested with the
ChirpStack catalog in the POC. The server profile UUID is a separate field.

Only reviewed models qualify. A custom profile called “S2101” does not establish
that identity. Add a `(vendor_id, catalog_model_id)` entry to `DEVICE_MODELS` for each tested model. Do not infer
a model from payload length or a user-supplied device name.

## Keep event interpretation in the model

The application forwards every event. The S2101 model accepts uplinks on its
supported port, decodes the bytes, and merges state. It ignores other events.
A model that supports battery status can consume `STATUS` in the same method.

The application listens for new models and then subscribes to model state. It does
not decode payloads or create models itself. Model `close()` releases listeners.
