---
title: Build a device library
description: Organize device models into a library with a public collection, a CLI, and tests.
---

A device library exposes a collection and the device models it manages.
Applications discover models through the collection, read their attributes,
subscribe to updates, and call their command methods.

Start with a model from [Devices and collections](/lorawan-connection/modelling/overview/).
That guide covers decoding, state, commands, and model lifecycle. This page shows
how those pieces fit into a Python package.

## Organize the package

Add `lorawan-connection` as a dependency in your package's `pyproject.toml`.
Keep device models and their decoders together. For a SenseCAP library, the layout
could be:

```text
pyproject.toml
sensecap_lorawan/
  __init__.py       # public exports
  s2101.py          # S2101 model and decoder
  collection.py    # supported device models
  __main__.py      # command-line entry point
tests/
  conftest.py      # collection fixture
  test_s2101.py
```

The [quickstart example](/lorawan-connection/getting-started/quickstart/#example-library)
contains the S2101 model and decoder. Put those in `s2101.py`. Add a module for each
new model; move decoders shared by several models into a separate module.

## Expose a collection

Declare the library's supported models in `collection.py`:

```python
from lorawan_connection import DeviceCollection

from .s2101 import S2101


class SenseCapDeviceCollection(DeviceCollection[S2101]):
    DEVICES = (S2101,)
```

The collection is the application's entry point for all supported devices on a
network. It creates models, routes their events, and reports additions and
removals. A device-added callback receives a model ready for the application to
observe.

Export the collection and model classes from `__init__.py`:

```python
from .collection import SenseCapDeviceCollection
from .s2101 import S2101

__all__ = ["S2101", "SenseCapDeviceCollection"]
```

This gives callers stable imports as the package grows. With several device
classes, use their union as the collection's type parameter and list them all
in `DEVICES`.

## Keep the application boundary clear

The library owns payload formats, ports, units, device commands, and reported
state. Its public attributes and methods let applications use devices without
interpreting LoRaWAN messages.

The application owns credentials, connection setup, and reconnection. Keep backend
imports in connection scripts such as the CLI. The device models use the shared
event and downlink interfaces. See [Connecting to ChirpStack](/lorawan-connection/connection/chirpstack/)
for a complete application using the SenseCAP collection.

## Add a CLI and tests

Expose a command with the [command-line helper](/lorawan-connection/patterns/cli/).
It accepts the collection's model classes, connects to a server, and prints device
updates. This lets users try the library with their devices.

Use the [testing guide](/lorawan-connection/patterns/testing/) to create a collection
fixture with a device already added. Test the library through its public model
attributes, command methods, and update listeners using captured payloads.
